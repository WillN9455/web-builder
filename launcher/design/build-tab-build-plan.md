## 1. Branch + sequencing decision (SA call)

**Branch `feature/build-tab`, stacked on `feature/design-tab` @ `00307a2` (PR #32 tip) — NOT off origin/main.**

Why: linear chain `#29 sprint → #32 design → build-tab` follows the established additive pattern. The Build journey is per-story on the same spine (`PRD/stories.md` US-NN grammar + `kanban_card` read model, via `requirements-model.ts` `parseStories` — design.ts already imports it there, not from story-gen). On main there is no canonical story list, and the design-tab implementation (notes, source cards, back-arrow, rules editor, `verify-design.ts` rig) is the direct template for the build story detail — CA2 reads it as a neighbor, not a copy-rewrite. PR #32 is DR2-approved at tip, so the stack is low-risk.

Constraints that make the rebase mechanical:
- **Zero edits to sprint-owned AND design-owned files** (`server/story-gen.ts`, `server/board.ts`, `server/jira-link.ts`, `server/design.ts`, `components/design/`, `_design.scss`, sprint scss). Build tab is purely additive: new server module, new client components, new scss partial.
- Shared registration seams (db.ts, index.ts, App.tsx, api.ts, app.scss, package.json) get additive appends in the same regions design-tab used — mechanical at rebase.
- Merge order: #29 → rebase #32 → rebase build-tab → re-run all gates at each committed tip → retarget PR base to `main` before merge (`gh pr create`, GitHub-hosted — never `buzz pr open`).
- **Review diff convention:** PR base stays `main`; reviewers assess the build-only delta `git diff 00307a2..build-tip` (same scoping-note convention as #32).

## 3. Server (`server/build.ts`, new — mounted in `server/index.ts` after design routes)

Route order matters: `…/build/rules` + `…/build/rules/agents/:agent` + `…/build/config` must be registered **before** the `GET …/build/:storyId` catch-all (design.ts precedent — otherwise `rules`/`config` parse as a storyId and 404).

| Route | Behavior |
|---|---|
| `GET /api/projects/:id/build/stories` | Story list from `PRD/stories.md` (reuse `parseStories` from `requirements-model.ts` — same import design.ts uses; no new grammar) joined with `build_story` state + `kanban_card` mapping + requirement titles. Returns **all** stories, each with `build_status` (null → not in build). Client renders the in-build list (non-null rows), 4 stat tiles, rework queue, agent strip from the same payload. Unknown project → 400 (parseProjectId pattern, board.ts:158/172/215). |
| `GET /api/projects/:id/build/rules` | One payload: `{architecture, config, rules, agents}` read from the project's `code-builder/` folder (`config-rules.md`, `build-rules.md`, `agents/{name}.md`). Missing files → seeded defaults (architecture defaults = AC-15 values: FE React 18 / BFF Express /api/* / BE Node 22 / DB SQLite better-sqlite3 / Host Vercel + Fly.io). Path resolved via the project-dir mechanism only; never invent paths. |
| `PUT /api/projects/:id/build/config` | `{key, value}`. **Closed key set** — only the FR-8 configuration keys (`Package manager`, `Node version`, `Linter`, `Formatter`, `Test runner`, `Env vars`, `Secrets handling`); unknown keys → 422. **Architecture keys (FE/BFF/BE/DB/Host) are NOT editable here** — the read-only card is the caption's promise; accepting them would be a silent lie. Values length-capped. Write-back: `code-builder/config-rules.md` (markdown `key: value` lines), resolveInside containment + fixed filename + tmp+rename atomic write + size cap (2 MB, design-rules precedent). Disk-verified in the gate. |
| `PUT /api/projects/:id/build/rules` | `{content}` markdown → `code-builder/build-rules.md`. Same guard family as design rules PUT: no `..` red-herring check (DR2 F-SEC-2 lesson — delete it, containment is the guarantee), `resolveInside` + fixed filename, tmp+rename, 2 MB cap. `GET` echoes saved bytes. |
| `PUT /api/projects/:id/build/rules/agents/:agent` | `{content}` → `code-builder/agents/{agent}.md`. `:agent` validated against the fixed set `code-1 | code-2 | code-3 | reviewer` (never used as a path segment from user input). Defaults seeded from `framework/build/skills/coding-guidelines.md` sectioned by agent + project additions. |
| `GET /api/projects/:id/build/:storyId` | Story + linked requirement card data + files + apis + notes. 404 unknown story (grammar-validate `:storyId` against `US-\d{2,}` — mirror `afae9ec`); **story-membership check scoped by project (the F-SEC-1 lesson from #32 — from day one, not a post-review patch)**. DR2 assertion 4: membership is confirmed by joining storyId against the project-scoped `stories.md` — the grammar match is a fast-path 404 only, not the membership proof. ID display note: route param is always `US-XX`; the `TM-XX` pill label is the display key from the kanban jira-key mapping (fallback `US-XX` when unmapped) — v5.4 requirements doc wins on the mockup conflict. |
| `POST /api/projects/:id/build/:storyId/files` | `{path, layer?}`. Validation: relative only, no leading `/`, no `..`, no NUL/control chars, length cap (≤ 300 chars) → 422 with the spec's message `Paths must be relative and inside the project folder.`. Duplicate → 409/inline warning `This file is already in the list.` (UNIQUE index + friendly pre-check). `layer` ∈ `new \| modified \| null`. **Paths are metadata strings in DB — never written to disk** (no traversal risk on storage; the validation is data hygiene, not containment). |
| `DELETE /api/projects/:id/build/:storyId/files/:fileId` | Integer id; delete `WHERE id=? AND project_id=? AND story_id=?` — a crafted foreign id must not touch another project's row (IDOR assert in the gate). |
| `POST /api/projects/:id/build/:storyId/apis` | `{tier, method, path, description}`. `tier` ∈ `bff \| be` (CHECK); `method` ∈ `GET/POST/PUT/PATCH/DELETE` (CHECK, §7); path must start with `/`, length caps on path/desc; per-field 422 errors. |
| `DELETE /api/projects/:id/build/:storyId/apis/:apiId` | Integer id, scoped delete as above. |
| `POST /api/projects/:id/build/:storyId/notes` | `{body}` — identical guard family to design (DR2 F-3): reject `<` (422, storage-guaranteed plain-text), body required, **10 KB cap** (F-SEC-1 lesson), author default `Will`, `.slice(0,80)`. |
| `POST /api/projects/:id/build/:storyId/transition` | `{to}` validated against the build-status enum → else 409 illegal. Enum + legal moves: `picked_up → building → self_review → ready_for_review → ready_for_qa → deployed_qa`; `rework → building` (Send back to Build; client confirm modal when `rework_issues > 0`); `rework` entered from QA/Review events (not via this route in v5.4 — no QA integration). **DR2 assertion 1: explicit legal-edge table in code — `ready_for_qa` reachable ONLY from `self_review`/`ready_for_review` (eligibility is server-enforced, not just the disabled button); no skip-ahead (`ready_for_review → deployed_qa` is illegal).** **No `kanban_card` writes this slice** — the Sprint board stays the authoritative spine; if a card flip is ever added, it must re-scope `WHERE id=? AND project_id=?` (design F-4 pattern, board.ts:244). |

Storage: new sqlite tables in `server/db.ts` following the `design_story`/`design_note` pattern —
- `build_story` (project_id, story_id, build_status, rework_origin, rework_issues, updated_at; UNIQUE(project_id, story_id)) — build_status CHECK: `picked_up | building | self_review | ready_for_review | ready_for_qa | deployed_qa | rework` (pill labels per FR-1; colours from the existing todo/inprog/review/done/blocked palette kit).
- `build_story_file` (project_id, story_id, path, layer CHECK(`new|modified`), created_at; UNIQUE(project_id, story_id, path)).
- `build_story_api` (project_id, story_id, tier CHECK(`bff|be`), method CHECK(GET/POST/PUT/PATCH/DELETE), route_path, description, created_at).
- `build_note` (project_id, story_id, author, body, created_at).
- Project-scoped indexes like design. If a CHECK rebuild migration is ever needed, follow the `jira_link 'pending'` temp-table rebuild pattern from PR #29 — `CREATE TABLE IF NOT EXISTS` keeps old CHECKs forever.

**IDOR / per-project scoping on every route (the operative RBAC — rbac-matrix is still the placeholder):** every route does `parseProjectId(req.params.id)` → null → reject, and every read/write carries `WHERE project_id = ?`. Story-scoped routes additionally verify story membership (project-scoped `stories.md` + scoped table rows) — a foreign storyId 404s, never renders.

**No uploads on this tab** — FE/BFF/BE entries are validated strings in DB. **Do not copy the design /source 12 mb shape-matching body gate**; keep the global 1 MB JSON parse (no new upload surface = no new exception). Rules/config PUT stay under the global cap with the 2 MB server-side byte pre-write.

## 6. Risks (SA-R, pre-flagged for Dev Reviewer 2)

- **SA-R-01** Stacked on #32 (which is stacked on #29): rebase conflicts if either moves. Mitigation: zero-touch on sprint + design files; mechanical rebase order in §1.
- **SA-R-02** Projects with no `stories.md` (sprint slice 4 never run): Build list renders the empty state, **no fallback to features/journeys** — same divergence-avoidance rule as SA-R-02 of the design plan.
- **SA-R-03** `server/index.ts:464` carries the committed literal NUL byte — grep-based edits silently become binary matches. Use `command grep -a`/python for searches; if that region is touched, restore the `\x00` as an ASCII escape, do not "fix" the file.
- **SA-R-04** Stored-XSS / injection surface is smaller than design (no HTML upload, no iframe): entries are validated metadata strings rendered as text — renderer must not inject raw paths/bodies as HTML; notes keep the design guard family (`<` rejection + escape-then-markdown, never `dangerouslySetInnerHTML` on raw body). File paths are never used in filesystem operations — a path like `../../etc/passwd` is data hygiene 422, not containment.
- **SA-R-05** Build transitions must stay **read-model-local** (no kanban_card writes, no Jira push) — sprint slice 4 owns the spine; double-writes would fight its reconcile logic. If kanban flips are ever added: re-scope `WHERE id=? AND project_id=?` (design F-4).
- **SA-R-06** Config PUT closed key set, arch keys excluded — prevents the "steering surface" from being silently rewired through the config endpoint (the architecture card's lock icon is a UI promise; the closed key set is its server-side enforcement).
- **SA-R-07** `err.message` 500-passthrough (S-1 @ #29) and the `TODO(auth)`/RBAC-matrix placeholder are pre-existing seams — unchanged by this tab, flagged so DR2 doesn't re-litigate them as build regressions.
- **SA-R-08** Story-entry semantics: no auto-entry from Design in this slice — the Build list shows stories with an existing `build_story` row (seed supplies demo rows). If the list renders as permanently empty in dev, check the seed first, not a new auto-creation path.
