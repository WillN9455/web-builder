Design & accessibility rules

writes to design-system/README.md + skills/accessibility-guidelines.md

Token discipline. Every color, spacing, type, and radius value in a Figma file or code file must reference a token from design-system/tokens/. No hex literals in components, no one-off fonts.

Interaction states (required per component). Every component spec defines default, hover, focus, active, disabled, loading, error, and empty. Figma variants use these names verbatim; code maps them to data-state attributes.

WCAG 2.1 AA, non-negotiable. All text and interactive elements meet the 4.5:1 contrast ratio (3:1 for large text ≥ 24px or 18.66px bold). Every form input has a <label> or aria-label. Every interactive element has a visible focus ring (2px navy with 2px offset).

Keyboard navigation. Every flow is usable with the keyboard alone. Tab order matches visual order; Esc closes modals and popovers; Enter and Space activate controls; focus is moved into modals on open and restored on close.

Layer naming. Figma layers use PascalCase for components and camelCase for variants and states (e.g. Button/Primary/Hover). No Frame 247, no Rectangle copy 3.

Assets. SVG over raster wherever possible; if a raster is needed it ships at 2x. Icons are 24×24 with a 1.5px stroke and inherit currentColor.

Touch targets. ≥ 44×44 px on every breakpoint < 1024px. Safe area. Mobile pages pad 16px from viewport edges; bottom tab bar adds env(safe-area-inset-bottom). No-hover state. Touch breakpoints must not depend on :hover alone — every hover state has a paired :focus or :active.

Per-agent design guidelines

one per Design Agent + Design Reviewer · writes to design-system/agents/{name}.md
DA1
Design Agent 1 — Hi-fi & components Active now · Designing TM-23 (Photo upload) · ~1h 20m elapsed

Scope. Owns high-fidelity frames, component variants, and interaction states inside Figma for assigned stories.

  • Start from the matching component spec in design-system/components/; never duplicate an existing component.
  • Token-first: every color, spacing, type, and radius pulls from design-system/tokens/. No hard-coded values.
  • Every variant ships all 8 interaction states (default, hover, focus, active, disabled, loading, error, empty).
  • Hi-fi frames at 1280px (desktop), 768px (tablet), and 375px (mobile) — same component, three frames.
  • Layer naming: PascalCase for components, camelCase for variants and states.
DA2
Design Agent 2 — Wireframes & flows Idle · last shipped TM-18 wireframes 2h ago

Scope. Owns low-fidelity wireframes, user-flow diagrams, and edge-case enumeration for assigned stories.

  • Wireframes are grayscale + placeholder text — no final color, no final imagery. Decisions live in the spec, not the wireframe.
  • Every flow diagram must enumerate the empty, error, validation, and forbidden states, not just the happy path.
  • Map every wireframe back to the linked requirement ID (e.g. TM-23). A wireframe with no parent requirement is rejected.
  • Reuse primitives (cards, lists, form rows) — do not invent one-off layouts when an existing component already covers the need.
DR1
Design Reviewer (peer) Active now · Reviewing TM-19 hi-fi · ~18m elapsed

Scope. Reviews another Design Agent's frames against the linked requirement, the design system, and the rules in this section.

  • Read the linked requirement first; the design exists to satisfy it. Drift from the requirement is a blocker, not a nit.
  • Audit every component for token usage and the full state set — no hex literals, no missing states.
  • Run the WCAG 2.1 AA checklist: contrast on every text/background pair, focus order, ARIA labels, keyboard reachability.
  • Approve only if the design passes all checks; otherwise leave specific, actionable comments (frame URL + element name + what to change).
