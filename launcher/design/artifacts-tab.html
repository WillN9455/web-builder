Tenant Maintenance Portal
Maintenance request app for property managers · v0.4 · last edited by BA Agent 2026-07-30

idea.md is the living source-of-truth for the project. The BA Agent and SA Agent edit it together during the intake chat; subsequent agents read it before producing any artifact.

Problem

Property managers at small-to-mid landlords spend 3–4 hours/day triaging maintenance requests across email, SMS, and phone. Tenants wait an average of 2.1 days for a status update. There is no audit trail.

Users (3 personas)
  • Pat — tenant at a 60-unit building. Files a request once a quarter. Mostly mobile.
  • Sam — property manager at a 200-unit portfolio. Handles 15–30 requests/day. Lives in the app.
  • Riley — vendor / contractor. Receives work orders. Mobile-first, on the job.
What's in scope for MVP
  • Tenant submits a request (text + photo).
  • Sam triages → assigns to Riley → status updates push to Pat.
  • Audit trail visible to all three.
  • Notifications via email + SMS (Twilio).
Pinned: the four MVP stories drive the 14 requirement IDs (BR-1 … BR-14) and the 14 Jira tickets (TM-1 … TM-14) that the Sprint board renders. See § Risks for what we explicitly cut.
Success metrics

Median request-to-assign time < 1h (baseline 4h). Tenant satisfaction (post-resolution survey) > 4.2/5. Vendor on-time arrival > 90%.
